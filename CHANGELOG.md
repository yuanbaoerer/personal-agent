# Changelog

All notable changes are recorded here. This project does not yet have a stable release or declared license.

## Unreleased

- L2R-01 (GH-02/#60, #68): `CredentialBroker` now persists non-secret ref metadata (`pa_credential_refs`) with owner/plugin/account/repositoryIds/scopes/expiry, keeps the epoch and revocation across restarts, and rejects undeclared scopes entirely; existing `github:default` must declare `repository.read` explicitly. GitHub typed reads resolve the binding credential with owner + immutable repositoryId checks. Router resolves a bare projectKey only through the owner's active ProjectBinding, binds `repo/repositoryId/projectKey/defaultBranch/allowedPlanPaths` into completion criteria, rejects ambiguous/unbound/mismatched projects, and the project-review Verifier rejects findings outside the bound repository/project. 466 tests pass; real OAuth/E3 remains blocked on owner credentials.
- Extension Platform V1 first slice merged to main: PR #74 (plugin runtime + GitHub plugin), #75 (SKILL.md runtime), #76 (read-only MCP host), #78 (task-level ExtensionPolicy), #79 (MCP DNS pinning), #82 (compiled MCP read-only contracts), with real acceptance evidence in #77. 438 tests pass; typecheck, secret scan, install smoke and deploy dry-run pass. CI recovered on 2026-11-21: main run `44889097865` passed test/macOS/Windows/install-smoke; the earlier stack merges were local-verified because Actions billing blocked their runs. Remaining: WorkProfile/ModeCatalog, MCP OAuth/stdio/writes, Feishu inbound and real OAuth negatives.
- EXT-03 follow-up: MCP non-trusted connections are pinned to the DNS address that passed validation via an undici Agent; `trustedHosts` remains an explicit proxy/on-prem bypass. Remote tools are now read-only only when a compiled `McpReadOnlyContract` matches provider, endpoint, contractVersion and remoteName; the built-in `github@1` contract allows only `get_commit` and `list_pull_requests`. Unverified tools/endpoints fail closed and are absent from the manifest. Response streams still hard-fail at 2 MiB.
- GH-02 first slice (#83–#85) added owner-scoped ProjectBinding (`pa_projects`), list/get/bind/unbind through the authenticated API, SDK and CLI, and typed GitHub reads with fixed revisions and active binding enforcement. Revoked bindings retain their history.
- GH-02 and GH-04 read-only review (#86–#88) bind project reads to credentials and immutable repository IDs, provide fixed-revision evidence and produce owner-reviewable Issue drafts. Follow-up hardening resolves chat reviews from the active project binding, rejects unscoped typed task reads, rechecks credential scope and validity, and verifies PR base and head around the file listing. Findings now check every citation and any declared GitHub claims against receipts. Reports distinguish model conclusions from validated citations. Issue drafts use verified issue detail receipts for the previous body hash. Real private-repo and Feishu acceptance and approved Issue writes remain open.

Conflicts require review; new Router tasks require structured claims and free text is never marked verified.
- Extension Platform V1 foundation: manifest schema and builtin plugin catalog with persisted lifecycle, atomic capability snapshot/generation, task/action plugin-version fences, hot enable/disable (Node), `pa plugins` and `/api/v1/plugins`; GitHub migrated to the first builtin Integration Plugin while preserving `github.read`, PAT/OAuth, allowlist and preauthorization. OAuth login/logout/account switch advances the catalog generation and revokes pending approvals. Third-party isolation and the full WorkProfile/ModeCatalog layer remain pending; real read-only GitHub and MCP evidence is recorded under `docs/acceptance/`.
- EXT-04 skills loader (Node): `SKILL.md` metadata index, digest/version/path/byte/plugin/permission checks, on-demand body injection into Worker prompts, pinned skill bindings on tasks, `GET /api/v1/skills` and `pa skills list`; built-in read-only `github.project-review`, `github.issue-management` and `github.project-digest` skills. Skill files never execute code and cannot grant tools or approvals.
- EXT-04 task-level ExtensionPolicy: host-supplied plugin/skill allowlists and `allow|require_approval|deny` permission ceilings persist on the task extension; creation validates the Mandate, catalog re-checks proposals/actions, and `require_approval` blocks preauthorization auto-approval. CLI flags and API schema included. WorkProfile/ExecutionStrategy/ModeCatalog resolution remains pending.

Real remote/GitHub MCP comparison, MCP OAuth, stdio, resume/pagination and any MCP write path remain pending.
